一年前我把博客搬到了 Notion。当时的理由很充分：写起来舒服，图片直接粘贴，手机也能改，不用碰命令行。

一年后我搬回来了。原因不是它不好用。

## 我为什么搬走

真正的问题出现在第三个月。我发现自己打开 Notion 之后，第一件事不是写正文，而是**填字段**。

状态改成「写作中」，选好分类，打上三个标签，挑一张封面图，填上摘要……等我做完这些，写作的冲动已经用掉了一半。

更糟的是，我开始为一个不存在的人写作。那个「读者」是 database 视图里的一个筛选条件，他关心的是文章的属性是否齐全，而不是内容是否有意思。

## 搬回静态站点的三个理由

**一、文件是我的。** Markdown 文件在本地磁盘上，用任何编辑器都能打开。十年后 Notion 还在不在我不知道，但 `.md` 一定还能读。

**二、写作和发布分离。** 我把草稿写在 `src/content/writing/` 里，文件就是文章。发布 = `git push`。中间没有「发布」这个需要思考的动作。

**三、约束是好事。** frontmatter 只有五个字段：标题、日期、标签、摘要、草稿。没有封面图字段，所以我永远不会花二十分钟去挑封面图。

## 代价是什么

要诚实地说，搬回来是有代价的：

- 手机上改不了。（我的解法：手机上只记事，不写作。）
- 图片要自己处理。（我的解法：写了一条命令，见下。）
- 没有多人协作。（这不是问题，本来就只有我一个人。）

最后一条其实最重要：**Notion 的能力里，我真正用到的不到 5%。** 剩下的 95% 只是让我在选择面前多停留了几秒。

## 图片这件事

对图文博客来说，图片流程决定了你会不会持续发图。我的原则是：**从拍完照到它出现在文章里，只能有两步。**

```bash
# 1. 把原图丢进 src/assets/images/writing/<文章名>/
# 2. 跑一下
npm run img
```

脚本做四件事：压到长边 1600px、生成三档宽度、按规范重命名、在终端打印一段可以直接粘进文章的 Markdown。

如果这个流程需要三步，我就不会发图了。这不是夸张，是过去三年反复验证过的结论。

## 现在的感受

搬回来三个月，我发了 9 篇文章——比在 Notion 的整个下半年都多。

不是因为静态站点更强大，恰恰相反，是因为它更弱。弱到我只能专注于写。
